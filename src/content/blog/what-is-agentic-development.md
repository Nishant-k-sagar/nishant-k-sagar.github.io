Before understanding agentic development, we first need to understand what an agent is in the first place. Having awareness about agents makes it easy to get an idea of agentic development. Throughout this series agent refers to an AI agent.

## What is an Agent

In simplest words - agent can be defined as an LLM wrapped in a system to perform some specific tasks/goal autonomously. Where LLM works as the brain of a complete system.

GFG defn : An AI agent is an autonomous software system that perceives its environment, makes decisions, and takes actions to achieve a specific goal.

Thus utilising and using the agents in software development or any other type of development can be loosely defined as agentic development.

## Why are they useful in development?

Agent’s capability to imitate human intelligence allows them to work on a large set of various domains. Their ability to reason on input and provide the output based on various factors has truly revolutionised the modern era. Also they are very great at following instructions and perform repetitive tasks with higher accuracy than average humans as Agents do not experience fatigue. Agents are very good at using tools provided as guidance. Also - They are faster at implementing and doing if steered properly. All these things provide a great support in agent’s usefulness.

## Understanding workflows

A workflow is a repetitive, step-by-step sequence of tasks to achieve some final output state.
Or simply say that a well defined set of progressive recurrent steps/stages to achieve the goal - can be simply defined as a workflow.
These workflows are used for solving similar problems. They avoid writing repetitive steps and make the building smooth.

## An insight into compound AI systems

Systems that execute/solve the AI tasks by combining multiple components rather than a simple LLM api call. These systems may involve suitable specific components, tools and technologies centered to address their domain specific use cases.

These components include multiple calls to models, retrievers, web searches, explorers and more. For example RAG applications include more than model calls, they need embedding models, searches, tool calls etc. Claude code and Codex also can be classified as compound AI systems.

[Compound AI systems](https://www.databricks.com/blog/what-are-compound-ai-systems)

## Understanding Agentic coding and comparing with conventions development

Agentic coding is just not faster code writing. Rather It is a complete paradigm shift. This is different from autocomplete, or suggestion tools which were speed helpers. Agentic coding introduces the autonomous loop. This provided the surface for plan - act - observe - iterate loop.
It is something which is derived from the real world working of software development.
Now coding agents are capable enough to generate the asked code. Thus Bottleneck has moved from writing line by line but verifying the code. Will it serve the purpose? Has it changed any other part of the codebase? Is it optimized for scale? And related verifications.

Also - It has diminished the layer of cross-domain fraction. Cross-domain fraction appears when the developer is not aware of the domain(as it may be completely separate knowledge). But LLMs are corpses of knowledge which have depleted this layer of fraction. Great innovation. But still need verification as LLMs come with warnings of may contain the wrong response.
